# Learn — where to answer each question from

The `explain` skill teaches from here. **Read the source, answer from it, render it into the user's
language.** Do not answer from memory, and do not invent a rule that is not written down — an
invented rule becomes real the moment the user follows it.

| What they are asking | Read this |
|---|---|
| "How does this actually work?" · "Why three levels?" · "Why must that file stay small?" | `system/tiers.md` |
| "Where should this go?" · "What's a domain?" · "Why does everything need a catalog row?" | `system/conventions.md` |
| "I've just finished setup — now what?" | `system/learn/first-week.md` |
| "How do I add a new area?" | `system/learn/adding-a-domain.md` |
| "What's a skill?" · "Will my skills work elsewhere?" | The limit stated in the `explain` skill — say it in full |
| "How do I set this up?" | `system/procedures/onboarding.md` |

**These files are the only copy.** If something here is wrong, fix it here rather than explaining
around it — and if the answer genuinely is not written anywhere, say so and offer to write it down.

Concepts live in `tiers.md` and `conventions.md`; the two files in this folder are walkthroughs for
things people actually do. Keep it that way — the moment a walkthrough restates the schema, there are
two copies of one rule and one of them will go stale.
